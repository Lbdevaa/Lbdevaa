  # Оптимизации фронтенда: рабочие правила

  Правила для любого React-приложения: SPA на Vite / webpack или Next.js. Названия API даны как пример (React Query,
  Redux, Vite); принцип переносится на аналоги. Источники и как применять —
  [README.md](README.md); зависимости — [dependency-hygiene.md](dependency-hygiene.md), безопасность приложения —
  [app-security.md](app-security.md).

  ## Как читать

  У каждого правила — уровень и способ найти нарушение:

  - **обязательно** — для любого проекта своего типа; нарушение — находка аудита;
  - **по ситуации** — только когда выполняется условие из правила; без условия нарушения нет;
  - **Найти:** — как обнаружить нарушение. Пометка *(авто)* — проверяет инструмент (линтер, CI), без неё — ручная
    проверка.

  Раздел 8 (Next.js) обязателен только для проектов на Next.js. Названия аудитов Lighthouse в строках «Найти» — по
  смыслу: в новых версиях часть аудитов переименована в insights. AI-агент сверяет API с документацией **той
  версии, что стоит в lock-файле** (у Next.js 16.2+ — `node_modules/next/dist/docs/`, у остальных — сайт или
  исходники по тегу), а не с памятью: данные обучения отстают от версии в проекте.

  ## Главное правило

  **Сначала метрика, потом оптимизация.** Три полевые метрики (Core Web Vitals):

  | Метрика | Что меряет | Хорошо | Плохо | Что обычно помогает |
  |---|---|---|---|---|
  | LCP | когда показан главный контент | ≤ 2.5 с | > 4 с | раннее обнаружение LCP-ресурса, водопады, бандл, кэш |
  | INP | задержка отклика на клик / ввод | ≤ 200 мс | > 500 мс | меньше работы в main thread, меньше DOM, лишние рендеры |
  | CLS | прыжки вёрстки | ≤ 0.1 | > 0.25 | размеры у картинок и встраиваний, шрифты, bfcache |

  Пороги — по **75-му перцентилю** реальных визитов, **отдельно для мобильных и десктопа**: страница «хорошая», если
  в норме три визита из четырёх.

  Цикл: полевые данные → худшая метрика на худшей странице → трасса в DevTools Performance → одна правка → снова
  метрика. Порядок по влиянию: **водопады запросов и размер бандла** → сторонние скрипты → лишние рендеры →
  микрооптимизации JS.

  **Найти:** в поле — библиотека `web-vitals` (`onLCP`, `onINP`, `onCLS`; сборка `attribution` показывает виновный
  элемент / взаимодействие), RUM в Sentry, CrUX через PageSpeed Insights и Search Console; в лаборатории — DevTools
  Performance (живые метрики, Insights, трек Layout Shifts), Lighthouse. **Lighthouse не меряет INP** (только TBT как
  приближение) — INP только в поле.

  ## 1. Доставка

  **1.1. HTML — `no-cache`, ассеты с хэшем — навсегда.** *обязательно*
  `index.html` — `Cache-Control: no-cache`: браузер перепроверяет его при каждом визите, и новый релиз подхватывается
  сразу. Файлы с хэшем в имени (`index-a1b2c3.js`) — `public, max-age=31536000, immutable`. Файлы без хэша (`logo.svg`,
  `manifest.json`, service worker) — короткий кэш. Не `no-store` на HTML: он отключает bfcache (1.6).
  **Найти:** заголовки ответа в DevTools → Network или `curl -I`.

  **1.2. Сжатие текстовых ответов: brotli, запасной вариант gzip.** *обязательно*
  JS, CSS, HTML, JSON, SVG при передаче уменьшаются на 65–85 %. Включается на сервере или CDN. Это не минификация (она
  при сборке) — нужны оба.
  **Найти:** заголовок `Content-Encoding: br` / `gzip` у текстовых ответов в Network.

  **1.3. CDN перед статикой.** *обязательно*
  Ассеты отдаются с ближайшего к пользователю узла; вместе с 1.1 — почти мгновенная загрузка при повторных визитах.
  **Найти:** TTFB ассетов из разных регионов (WebPageTest), заголовки CDN в ответе.

  **1.4. Code splitting по маршрутам и тяжёлым виджетам.** *обязательно*
  Каждая страница и всё тяжёлое, что открывается по действию (редактор, плеер, эмодзи, оплата), — через динамический
  `import()`. При сбое загрузки чанка — один повтор (помогает при сетевой ошибке; ошибка разбора модуля кэшируется
  навсегда, а HTTP-кэш может вернуть ту же ошибку), затем перезагрузка страницы один раз с защитой от цикла (в Vite —
  событие `vite:preloadError`). Перезагрузка помогает, только если выполнено 1.1, — иначе браузер снова получит старый
  HTML со ссылками на удалённые после деплоя чанки.
  **Найти:** bundle analyzer (initial-чанк содержит страницы и тяжёлые виджеты?); поиск `import()` и обработчика ошибки
  чанка; ошибки «Failed to fetch dynamically imported module» в Sentry после релиза.

  **1.5. Путь в `import()` — виден при сборке.** *обязательно*
  Карта загрузчиков `{home: () => import('./home')}` вместо `import(MODULES[name])` или шаблонной строки: иначе бандлер
  либо не разделит код, либо захватит всё, что подходит под шаблон. В `next/dynamic` путь обязан быть литералом.
  **Найти:** поиск `import(` с переменной или шаблонной строкой.

  **1.6. Страница пригодна для bfcache.** *обязательно*
  Возврат «назад» / «вперёд» из bfcache — мгновенный и без сдвигов вёрстки. Ломают: `Cache-Control: no-store` на HTML,
  обработчики `unload` (вместо них — `pagehide` / `visibilitychange`), незакрытые соединения на момент ухода.
  **Найти:** DevTools → Application → Back/forward cache → «Test back/forward cache» (показывает причины отказа); в поле
  — Not Restored Reasons API; поиск `addEventListener('unload'`.

  **1.7. Код тяжёлого экрана — заранее, по намерению.** *по ситуации: экран открывается по действию и грузится
  заметно*
  `import('./Editor')` на `onMouseEnter` / `onFocus` кнопки, которая его открывает: к клику чанк уже загружен. Для
  данных — 2.4.
  **Найти:** Network при клике — чанк начинает грузиться только после клика.

  **1.8. Следить за стартовым бандлом.** *обязательно*
  Tree shaking бандлер делает сам; задача — не втащить тяжёлую библиотеку в стартовый граф одним импортом. Раз в релиз
  смотреть, что попало в initial-чанки. Автоматическая защита — 10.1.
  **Найти:** bundle analyzer (`vite-bundle-visualizer` / `rollup-plugin-visualizer`, `source-map-explorer`; в Next.js
  16.1+ — `next analyze`, снимок до / после — `next analyze --output`).

  ## 2. Загрузка данных

  **2.1. Без водопадов запросов.** *обязательно*
  Каждая «ступенька» — полный round-trip, на мобильной сети 250+ мс. Три источника:
  - *последовательные запросы*: второй ждёт `id` из первого. Лучшее решение — на стороне API (один запрос вместо двух);
    независимые — параллельно (`Promise.all`, несколько `useQuery`);
  - *вложенные компоненты*: родитель не рисует ребёнка, пока не загрузил своё, а ребёнок тоже грузит. Поднять запрос
    ребёнка в родителя или запустить оба на уровне маршрута;
  - *ленивый компонент со своим запросом*: `HTML → JS страницы → данные → JS компонента → его данные` — пять ступенек.
    Запустить загрузку данных параллельно с загрузкой чанка.

  Водопады появляются незаметно (добавили запрос в ребёнка, перенесли компонент) — проверять регулярно.
  **Найти:** DevTools → Network на холодной загрузке ключевых страниц: «лесенка» вместо параллельных полос.

  **2.2. С Suspense несколько запросов в компоненте — одним вызовом.** *по ситуации: используется Suspense для
  данных*
  Каждый приостанавливающий запрос (`useSuspenseQuery`) останавливает рендер, и следующий не стартует. Несколько
  запросов — одним `useSuspenseQueries` или prefetch заранее. Без Suspense обычные хуки идут параллельно.
  **Найти:** два и более `useSuspenseQuery` в одном компоненте.

  **2.3. Серверные данные — с осмысленным временем свежести.** *обязательно*
  В React Query по умолчанию данные устаревают сразу и перезапрашиваются при каждом монтировании, фокусе окна и
  восстановлении сети; ошибка — 3 тихих повтора. Задать `staleTime` по природе данных: справочники и редко меняющееся —
  минуты; не меняющееся за сессию (флаги при старте, права после входа) — `'static'` (не перезапрашивается даже при
  ручной инвалидации) или `Infinity` (если ручная инвалидация нужна).
  **Найти:** `staleTime` в `QueryClient` по умолчанию и у справочных запросов; в Network — повторные запросы при
  переключении вкладки браузера.

  **2.4. Prefetch по намерению.** *по ситуации: переход легко предсказать*
  Данные — на hover / focus ссылки (`queryClient.query(...)` / `prefetchQuery`) или на уровне маршрута до рендера.
  При prefetch **обязательно** задавать `staleTime`, иначе он перезапросит и свежие данные.
  **Найти:** Network при наведении и переходе — данные следующего экрана грузятся только после клика.

  **2.5. Ключ запроса — все входные данные.** *обязательно*
  Всё, от чего зависит загрузка (id, фильтры, страница, язык), — в ключе, иначе кэш отдаст ответ для других
  параметров.
  **Найти:** *(авто)* `@tanstack/eslint-plugin-query`, правило `exhaustive-deps`.

  **2.6. Поиск по вводу — debounce + последний ответ побеждает.** *по ситуации: запрос на каждый ввод*
  Запрос после паузы в вводе (ориентир — 300 мс; debounce на значении до ключа запроса), ответы старых запросов
  отбрасываются. В React Query на экран попадает ответ только по текущему ключу, но **сетевой запрос по умолчанию не
  отменяется** — даже при размонтировании. Отмена работает, только если `signal` из `queryFn` передан в `fetch` /
  axios. Запрос из эффекта без библиотеки — cleanup, игнорирующий устаревший ответ, или `AbortController`.
  `useDeferredValue` и `startTransition` гонку не решают и лишних запросов не убирают.
  **Найти:** Network при быстром наборе — запрос на каждый символ; `queryFn` без `signal`; `fetch` в эффекте без
  cleanup.

  **2.7. Соединение со сторонним доменом — заранее, если иначе нельзя.** *по ситуации: критичный ресурс на другом
  домене*
  Порядок выбора: сделать ресурс видимым в исходном HTML и поднять приоритет (3.1) → `preload` → и только если ни то,
  ни другое невозможно — `preconnect` (экономит 100–500 мс; DNS — 20–120 мс). `preconnect` — только к критичным
  доменам, используемым в ближайшие секунды: неиспользованное соединение браузер закрывает через 10 с, лишние
  конкурируют за канал; остальные — `dns-prefetch`. Шрифтам — атрибут `crossorigin`. `preconnect` и `dns-prefetch` —
  отдельными тегами (в одном теге Safari отменяет preconnect). К собственному домену — бесполезно. В React 19 —
  `preconnect()` / `prefetchDNS()` из `react-dom`.
  **Найти:** Network → колонка Connection / Waterfall: долгий DNS + TLS перед первым запросом к стороннему домену.

  ## 3. Картинки, шрифты и вёрстка (LCP, CLS)

  **3.1. LCP-ресурс — виден браузеру сразу и с высоким приоритетом.** *обязательно*
  Главное для LCP — не размер картинки, а когда браузер о ней узнал. Целевые доли LCP: TTFB ~40 %, задержка начала
  загрузки < 10 %, загрузка ~40 %, задержка отрисовки < 10 %. LCP-картинка — `<img src>` в разметке (для фона из CSS
  и шрифтов — `preload`) с `fetchpriority="high"`; `fetchpriority="high"` — не больше чем на одну-две картинки;
  скрытым слайдам карусели — `fetchpriority="low"`; критичные ресурсы — на том же домене, что и HTML. **В SPA с
  клиентским рендером** картинки нет в исходном HTML — браузер узнаёт о ней после загрузки и выполнения JS: нужен
  `<link rel="preload" as="image" fetchpriority="high">` в `index.html` или `preload()` как можно раньше в коде.
  LCP-картинку **никогда** не грузить лениво.
  **Найти:** Lighthouse — LCP-элемент и разбивка LCP по частям; DevTools Performance → insight «LCP breakdown» (доля
  задержки начала загрузки); `loading="lazy"` на картинке первого экрана.

  **3.2. Картинки ниже первого экрана — `loading="lazy"`, все — с размерами.** *обязательно*
  У каждой картинки — `width` / `height` или `aspect-ratio`, иначе сдвиг вёрстки при загрузке; у вариантов в `srcset` —
  одинаковые пропорции.
  **Найти:** Lighthouse — картинки без явных размеров (insight «Layout shift culprits»); трек Layout Shifts в DevTools.

  **3.3. Картинка по размеру места.** *обязательно*
  `srcset` + `sizes` с 2–3 вариантами ширины, форматы AVIF / WebP. Пользовательские фото ресайзит бэкенд или CDN по
  параметру. Размер — третий по важности фактор LCP после 3.1 («tends not to be a significant bottleneck»), но
  трафик на мобильных он решает.
  **Найти:** Lighthouse — доставка изображений (размер больше места, устаревший формат); Network — вес картинок на
  мобильной ширине.

  **3.4. Место под позднее содержимое — зарезервировано.** *обязательно*
  Реклама, встраивания, iframe, баннеры, подгружаемые блоки — `min-height` / `aspect-ratio` по наименьшему ожидаемому
  размеру, резерв не схлопывать. Новое содержимое не вставлять над существующим без действия пользователя —
  скелетон или наложение. Сдвиги в пределах 500 мс после ввода пользователя в CLS не считаются, при скролле — считаются.
  **Найти:** DevTools Performance → трек Layout Shifts и Insight «Layout shift culprits»; `web-vitals` attribution в поле.

  **3.5. Шрифты — свои, со стратегией подмены.** *обязательно*
  Файлы WOFF2, минимум начертаний, на своём домене; `preload` критичного шрифта первого экрана. Выбор `font-display`:
  `swap` — текст виден сразу, но при подмене шрифта будет сдвиг; `optional` — без сдвига, но на первом визите может
  остаться запасной шрифт. Сдвиг при `swap` убирает подгонка метрик запасного шрифта (`size-adjust`,
  `ascent-override`, `descent-override`, `line-gap-override`; в Next.js — `next/font` делает это сам). Сторонний CSS
  шрифтов через `@import url(...)` — нет: он встаёт в цепочку блокирующих запросов.
  **Найти:** Network — запросы к `fonts.googleapis.com` и `@import` в CSS; трек Layout Shifts при загрузке шрифта.

  **3.6. `preload` — только для того, что браузер иначе найдёт поздно.** *по ситуации*
  Один-два ресурса: LCP-картинка из CSS или JS, шрифт первого экрана. Каждый `preload` используется на этой же
  странице.
  **Найти:** предупреждение консоли «resource was preloaded but not used».

  ## 4. React: рендеры

  **4.1. State живёт там, где используется.** *обязательно*
  Состояние подсказки — внутри `Search`, а не в `App`: перерисовывается только тот, кому это нужно. Часто это решает
  проблему без мемоизации — вынести поле ввода с его state в отдельный компонент.
  **Найти:** React DevTools → Profiler, «Highlight updates when components render»: при вводе мигает весь экран.

  **4.2. Узкая подписка.** *обязательно*
  Компонент подписывается ровно на то, что рисует:
  - селектор возвращает готовое значение, а не сырые данные: `useSelector((s) => s.items.length > 0)` перерисует только
    при смене `true` / `false`; в React Query — `select: (data) => data.length`, функцию `select` выносить из компонента;
  - значение, которое читается только в обработчике, — не подписка, а чтение в момент события (`store.getState()`,
    `new URLSearchParams(location.search)`);
  - результат запроса не деструктурировать через rest (`const {data, ...rest} = useQuery()`): React Query следит, какие
    поля читаются, rest читает все.
  **Найти:** *(авто)* `@tanstack/query/no-rest-destructuring`; поиск `useSelector((s) => s.<слайс>)` целиком; Profiler.

  **4.3. Контекст — по одной теме.** *обязательно*
  Часто меняющиеся данные (онлайн-статус, курсор) — в отдельном контексте от редко меняющихся (язык, пользователь).
  **Найти:** провайдеры, в `value` которых смешаны частые и редкие поля; Profiler — перерисовка всех потребителей.

  **4.4. Мемоизация — компилятором, ручная — по замеру.** *обязательно*
  React Compiler (стабилен с 1.0, 07.10.2025) мемоизирует компоненты и хуки сам — но молча пропускает код, нарушающий
  правила React. Поэтому:
  - существующие `memo` / `useMemo` при включении компилятора не удалять массово — это меняет то, что он сгенерирует;
  - код, который полагается на мемоизацию ради **корректности** (эффект зависит от стабильной ссылки), ломается
    первым — точечное исключение `"use no memo"`;
  - компилятор не делит результат между компонентами: тяжёлое вычисление для многих компонентов — кэш вне React
    (модульный `Map`);
  - без хорошего покрытия тестами — **точная версия компилятора** (`--save-exact`), обновление вручную;
  - без компилятора — `memo` / `useMemo` только там, где замер показал ≥ 1 мс на вычисление или лишние рендеры тяжёлого
    узла; не на простых выражениях с примитивным результатом. `useMemo` не ускоряет первый рендер.
  Мерить — в **продовой** сборке с замедлением CPU в DevTools: в dev StrictMode рендерит дважды.
  **Найти:** React DevTools — значок «Memo ✨» у скомпилированных компонентов; `console.time` вокруг вычисления;
  версия `babel-plugin-react-compiler` в `package.json` без `^`.

  **4.5. Не объявлять компонент внутри компонента.** *обязательно*
  `const Avatar = () => ...` в теле родителя — новый тип на каждый рендер: React пересоздаёт его, теряются state и
  фокус в инпуте, эффекты перезапускаются. Компилятор этого не лечит. Компонент — на уровне модуля, данные — через props.
  **Найти:** *(авто)* `eslint-plugin-react-hooks`, правило `static-components`.

  **4.6. Эффект — только для синхронизации с внешним миром.** *обязательно*
  - производное значение — в рендере, а не `useEffect → setState` (лишний рендер и кадр со старыми данными);
  - реакция на действие пользователя — в обработчике, а не в эффекте, следящем за флагом;
  - сброс состояния при смене сущности — `key`;
  - уведомить родителя — в том же обработчике события (React объединит обновления в один рендер), а не эффектом;
    данные ребёнка не передавать родителю через эффект — поднять запрос в родителя;
  - подписка на внешний источник (`navigator.onLine`, `matchMedia`, сторонний стор) — `useSyncExternalStore`, а не
    эффект + state.
  **Найти:** *(авто)* `eslint-plugin-react-hooks`: `set-state-in-effect`, `set-state-in-render`.

  **4.7. Тяжёлая перерисовка по вводу — с низким приоритетом.** *по ситуации: ввод тормозит из-за перерисовки*
  Поле ввода обновляется сразу, отфильтрованный список — через `useDeferredValue` (значение — примитив или объект,
  созданный вне рендера) или `startTransition`. Ограничения: обновления state **после `await`** внутри
  `startTransition` не считаются transition — их оборачивать в `startTransition` ещё раз; transition нельзя
  использовать для управления текстовым полем.
  **Найти:** DevTools Performance — длинные задачи на каждое нажатие клавиши.

  **4.8. Частые временные значения — в `useRef`.** *обязательно*
  Позиция скролла, координаты мыши, id таймера — если не рисуются, хранить в ref: запись в state перерисовывает
  компонент на каждое событие. Читать и писать `ref.current` — в обработчиках и эффектах, не в рендере.
  **Найти:** `setState` в обработчиках `scroll` / `mousemove` / `pointermove`; *(авто)* правило `refs`.

  **4.9. Тяжёлая скрываемая панель — `<Activity>`.** *по ситуации: панель часто открывают и закрывают*
  `<Activity mode={open ? 'visible' : 'hidden'}>` (React 19.2) сохраняет state и DOM без пересоздания. Ограничения:
  - скрытые дети **продолжают перерисовываться** (с низким приоритетом) — скрытыми держать только то, к чему вероятно
    вернутся;
  - DOM не удаляется: `<video>` / `<audio>` продолжают играть — останавливать в cleanup `useLayoutEffect`;
  - prerender скрытой панели загружает данные только через Suspense (`use`, `useSuspenseQuery`), не из эффекта;
  - со внешним стором (Redux, Zustand — `useSyncExternalStore`) — **только React ≥ 19.3**: раньше изменения стора,
    пока Activity скрыт, терялись.
  **Найти:** версия `react`; медиа-элементы внутри `<Activity>` без cleanup.

  **4.10. Длинные списки — виртуализация.** *по ситуации: сотни строк и больше*
  Через библиотеку (`react-virtuoso`, `@tanstack/react-virtual`): строки разной высоты, подгрузка, восстановление
  скролла уже решены.
  **Найти:** Elements — тысячи узлов списка в DOM; медленный скролл в Performance.

  **4.11. Инициализация приложения — один раз на загрузку.** *обязательно*
  Аналитика, сокет, SDK — флаг на уровне модуля или код в точке входа до `createRoot`, а не `useEffect` в корне: в
  StrictMode эффект срабатывает дважды, при пересоздании корня — снова. Не злоупотреблять кодом на верхнем уровне
  модулей — он выполняется при импорте, даже если компонент не рисуется.
  **Найти:** `useEffect(..., [])` в корневом компоненте, инициализирующий глобальное; двойные события аналитики в dev.

  ## 5. Браузер

  **5.1. Анимации — через `transform` и `opacity` или View Transitions.** *обязательно*
  Сдвиг — `translateX`, а не `left`; появление — `opacity`, а не `height`: их анимирует композитор без пересчёта
  раскладки. Переходы между состояниями — `<ViewTransition>` (React 19.3) поверх браузерного View Transition API.
  Правило UX: fallback Suspense появляется сразу, без анимации; анимируется только переход от fallback к контенту;
  уже загруженное — без анимации.
  **Найти:** Lighthouse «Avoid non-composited animations»; поиск `transition` / `@keyframes` по `top`, `left`,
  `width`, `height`, `box-shadow`.

  **5.2. Сначала все чтения геометрии, потом все записи.** *обязательно*
  В цикле не чередовать `offsetWidth` и `style.width`: сначала собрать размеры, затем применить изменения (или сменить
  класс одним действием) — раскладка считается один раз.
  **Найти:** DevTools Performance — красный треугольник на «Recalculate Style» / «Layout» (forced reflow).

  **5.3. Каждая подписка — с отпиской.** *обязательно*
  `addEventListener`, `setInterval`, `setTimeout`, сокеты, observer'ы — в `useEffect` с cleanup, который снимает ровно
  то, что повесил. Глобальные синглтоны модуля — исключение.
  **Найти:** `useEffect` с `addEventListener` / `setInterval` без `return`; рост числа слушателей в DevTools →
  Memory / Performance monitor при навигации туда-обратно.

  **5.4. Слушатели прокрутки на элементах — `{passive: true}`.** *по ситуации: `touchstart` / `touchmove` / `wheel`
  на элементе*
  На `window`, `document`, `<html>`, `<body>` браузеры уже делают их passive по умолчанию. На элементах — нет: браузер
  ждёт обработчик перед прокруткой. Указывать `{passive: true}`, если `preventDefault()` не нужен; если нужен (свой
  свайп, зум) — на корне явно `{passive: false}`.
  **Найти:** поиск `addEventListener('touchstart'` / `'touchmove'` / `'wheel'` на элементах без `passive`; предупреждение
  консоли «Added non-passive event listener».

  **5.5. localStorage — в `try/catch`, с версией ключа и минимумом данных.** *обязательно*
  `setItem` бросает `QuotaExceededError` при нехватке места, доступ к хранилищу — `SecurityError`, если пользователь
  запретил хранение (например, заблокировал cookie). Ключ с версией (`prefs:v2`) — смена формата без падений на старых
  данных. Только нужные UI поля; токены и персональные данные — никогда. Частые чтения — кэшировать в памяти:
  хранилище синхронное.
  **Найти:** поиск `localStorage.` / `sessionStorage.` вне `try`; `JSON.parse(localStorage.getItem(...))` без проверки.

  **5.6. Меньше DOM.** *обязательно*
  Большой DOM удорожает каждый пересчёт стилей и раскладки — прямой вклад в INP. В SPA отдельно — цена рендеринга
  HTML через JS. Скрытое и далёкое за экраном — не рендерить или `content-visibility: auto`.
  **Найти:** Lighthouse «Avoid an excessive DOM size»; `document.querySelectorAll('*').length` на тяжёлых экранах.

  ## 6. Main thread и INP

  **6.1. Медленное взаимодействие — сначала найти в поле.** *обязательно*
  INP складывается из задержки ввода (длинные задачи в этот момент, особенно при старте), обработки и отрисовки.
  Сначала — какое взаимодействие и на какой странице медленное (`web-vitals` attribution, RUM), потом — воспроизвести в
  DevTools с замедлением CPU.
  **Найти:** `onINP` с attribution в RUM; без RUM — CrUX в PageSpeed Insights.

  **6.2. Длинную задачу — порциями.** *обязательно*
  Задача дольше 50 мс — длинная. Делить на порции и уступать управление: `await scheduler.yield()` (Chrome / Edge
  129+, Firefox 142+; **в Safari нет**) с запасным `setTimeout(0)` — однострочник `await globalThis.scheduler?.yield?.()`
  или полифил `scheduler-polyfill`. Уступать не после каждой функции, а по дедлайну — когда с последней уступки прошло
  ~50 мс. `isInputPending()` не использовать. В React — некритичное обновление через `startTransition`.
  **Найти:** DevTools Performance — задачи с красной штриховкой (блокирующая часть сверх 50 мс).

  **6.3. Сначала отклик, потом остальное.** *обязательно*
  В обработчике клика — сначала обновить видимое (открыть модалку, подсветить кнопку), аналитику, запись в storage и
  прочее — после отрисовки кадра: `requestAnimationFrame(() => setTimeout(work, 0))` или `scheduler.yield()`.
  `requestIdleCallback` — **только с запасным вариантом**: в Safari он выключен по умолчанию.
  **Найти:** обработчики событий, где до обновления UI идут аналитика / storage / тяжёлые вычисления; Performance —
  длинная задача между кликом и кадром.

  **6.4. Вычисления на сотни миллисекунд — в Web Worker.** *по ситуации*
  Парсинг больших файлов, обработка изображений, шифрование — в worker, обмен через `postMessage` (большие бинарные
  данные — transferable `ArrayBuffer`).
  **Найти:** Performance — одна задача на сотни мс в вашем коде, которую нельзя разбить порциями.

  ## 7. Сторонние скрипты

  **7.1. Аналитика и пиксели — после первой отрисовки и только где нужны.** *обязательно*
  GTM, пиксели рекламных сетей, тепловые карты, чаты поддержки — после `load` или первого взаимодействия: в Next.js —
  `<Script strategy="lazyOnload">` и только в layout / странице, где скрипт нужен; в SPA — динамическая вставка
  скрипта (по первому взаимодействию или таймеру; `requestIdleCallback` — с запасным `setTimeout`) с очередью-заглушкой
  (`window.fbq = (...a) => queue.push(a)`), чтобы ранние события не терялись. `<script>` без `async` / `defer` в
  `<head>` блокирует разбор страницы. Каждый такой скрипт — отдельный пункт в бюджете страницы.
  **Найти:** Lighthouse «Reduce the impact of third-party code»; Network — сторонние запросы до LCP; синхронные
  `<script src>` в `index.html`.

  ## 8. Next.js

  **8.1. Граница `'use client'` — как можно ниже.** *обязательно*
  `'use client'` — на входе в интерактивное поддерево (кнопка, форма), не на странице целиком: всё, что импортирует
  клиентский файл, уезжает в браузер. Server Component внутрь клиентского — через `children` / props, а не импортом.
  Общий компонент без директивы — оборачивать в клиентскую обёртку, а не добавлять директиву в сам компонент.
  **Найти:** `next analyze` — тяжёлые модули в клиентском графе маршрута; `'use client'` в `page.tsx` / `layout.tsx`.

  **8.2. В клиентский компонент — только нужные поля.** *обязательно*
  Всё, что передаётся клиентскому компоненту, сериализуется в HTML и JS. Поля, а не весь объект из базы; один объект —
  один раз.
  **Найти:** props клиентских компонентов с типами целых сущностей БД.

  **8.3. Тяжёлая работа с результатом-HTML — на сервере.** *обязательно*
  Подсветка синтаксиса, markdown, статичные графики в клиентском компоненте тянут в бандл всю библиотеку ради готовой
  разметки. Без браузерных API и интерактива — Server Component.
  **Найти:** `next analyze` — `prism` / `shiki` / `marked` / библиотеки графиков в клиентском бандле.

  **8.4. Серверные запросы — параллельно, без дублей и без лишних обращений к себе.** *обязательно*
  Независимые `await` — `Promise.all` или параллельные компоненты под отдельными `<Suspense>`; одинаковый запрос за один
  рендер — `React.cache()`; некритичная работа после ответа — `after()`. Server Component не вызывает собственные
  Route Handlers — данные напрямую.
  **Найти:** последовательные `await` независимых запросов; `fetch('/api/...')` в Server Components.

  **8.5. Request-time API — под `<Suspense>`.** *обязательно*
  Компонент, читающий `cookies()` / `headers()` / `searchParams`, — в `<Suspense>`, чтобы остальная страница
  пререндерилась; иначе динамической становится вся страница.
  **Найти:** вывод `next build` — маршруты, ставшие динамическими.

  **8.6. Server Actions — как публичные API.** *обязательно*
  Action доступна прямым POST-запросом, даже если нигде не импортирована, а проверка на странице на неё не
  распространяется. Подробно — [app-security.md](app-security.md), 8.1.
  **Найти:** `'use server'` без проверки сессии и прав в начале action.

  **8.7. Hero с разными картинками для мобильного и десктопа — `getImageProps()`.** *по ситуации*
  `srcSet` для обеих версий в `<picture>`, `fetchPriority="high"` на `<img>` — без `preload`, который не знает про
  `media` и заставил бы скачивать обе.
  **Найти:** два `preload` / две `<Image priority>` для одной позиции.

  **8.8. Библиотеки-барели — `experimental.optimizePackageImports`.** *по ситуации: барель не из списка по
  умолчанию*
  MUI, `lucide-react`, `date-fns`, `lodash-es`, `react-icons/*` и др. оптимизируются автоматически — добавлять нужно
  только остальные.
  **Найти:** `next analyze` — барель с сотнями модулей при паре использованных.

  ## 9. Сборка и зависимости

  **9.1. Цель сборки — по реальным браузерам аудитории.** *обязательно*
  Транспиляция под ES5 / ES2015 «на всякий случай» раздувает бандл и тянет полифилы для всех. Цель — из browserslist /
  статистики аналитики. Бандлер делает только синтаксические преобразования: новые методы и DOM-API без полифила
  падают в старом браузере молча. Для старых браузеров, если они действительно есть, — отдельная legacy-сборка через
  `nomodule`, современные браузеры её не скачивают. В Vite — `@vitejs/plugin-legacy`: `targets` — для legacy-сборки, в
  современной сборке полифилов нет (`modernPolyfills: true` без явного списка добавляет ~15 КБ `core-js` всем;
  `modernTargets` — только при `renderLegacyChunks: false`). При строгом CSP хэши inline-скриптов legacy-сборки — из
  `cspHashes` пакета, а не руками.
  **Найти:** `build.target`, browserslist, настройки plugin-legacy; `core-js` в современных чанках (bundle analyzer).

  **9.2. Стоимость зависимости — до установки.** *обязательно*
  Размер в бандле (bundlephobia, bundlejs, Import Cost в редакторе) и нативная замена (`Intl`, `structuredClone`,
  `URLSearchParams`, `AbortController`, `Set`, `fetch`). Импорт точечный: функция из `lodash-es`, только нужные локали
  библиотеки дат. Проверки безопасности нового пакета — [dependency-hygiene.md](dependency-hygiene.md), 2.4.
  **Найти:** при ревью — новые строки в `dependencies`; bundle analyzer — целые библиотеки ради одной функции.

  **9.3. Одна версия каждой библиотеки.** *обязательно*
  Две версии React, UI-кита или date-библиотеки в бандле — двойной код.
  **Найти:** `npm ls <пакет>`; bundle analyzer — один пакет в нескольких путях. Исправление — `npm dedupe` или
  `overrides`.

  **9.4. Импорт из файла, а не из barrel.** *обязательно*
  `import {slash} from './utils/slash'`, а не из `./utils`: dev-сервер и тестовый раннер загружают и трансформируют
  каждый файл barrel'а. В продовой сборке tree shaking это обычно вырезает — цена barrel'ов в скорости dev и тестов и
  в побочных эффектах модулей, мешающих tree shaking. Для внешних библиотек — 8.8 или прямой импорт по пути.
  **Найти:** `index.ts` с `export * from`; медленный старт dev-сервера (`vite --debug transform`).

  ## 10. Защита от регресса

  **10.1. Бюджеты в CI.** *обязательно*
  Размер стартового JS (`size-limit` или проверка по манифесту сборки), Lighthouse CI с порогами LCP / TBT / CLS. PR,
  который превышает бюджет, видно до мержа.
  **Найти:** в CI нет шага, падающего при росте бандла.

  **10.2. Полевые метрики — с разрезом.** *обязательно*
  Web Vitals с реальных пользователей с тегами страницы, устройства и релиза: видно, какой релиз и на каких экранах
  ухудшил метрику.
  **Найти:** в RUM нельзя отфильтровать метрику по релизу и типу устройства.

  **10.3. Lint-правила вместо памяти ревьюера.** *обязательно*
  - `eslint-plugin-react-hooks`, пресет `recommended`: правила хуков и правила компилятора (`static-components`,
    `set-state-in-effect`, `set-state-in-render`, `refs`, `purity`, `immutability`, `globals`). **Работает без
    установленного компилятора**;
  - `@tanstack/eslint-plugin-query`: `exhaustive-deps`, `no-rest-destructuring`;
  - `eslint-plugin-jsx-a11y` — доступность.
  **Найти:** конфиг ESLint без этих пресетов или с отключёнными правилами.

  ## Знать, применять по поводу

  | Техника | Повод |
  |---|---|
  | `content-visibility: auto` | длинная статичная страница или список без виртуализации |
  | `contain: layout paint` | изолированный виджет, который часто перерисовывается (график, плеер) |
  | Critical CSS inline | серверный рендер / статический лендинг, где LCP упирается в CSS |
  | Service Worker с кэшем | приложению нужен офлайн-режим (PWA) |
  | Selective hydration, `<Activity>` как граница гидратации | SSR со стримингом |
  | OffscreenCanvas | анимации и визуализации на canvas с тысячами объектов |
  | WebAssembly | готовая библиотека на C++/Rust (кодеки, обработка изображений) |
  | `Set` / `Map` вместо `includes` / `find`; `toSorted()` | горячий цикл с поиском по большому массиву |
  | Анимировать обёртку, а не `<svg>`; округлять координаты SVG | анимированные иконки, тяжёлые SVG |
  | `{count > 0 ? … : null}` вместо `{count && …}` | условие может быть `0` / `NaN` — иначе на экране «0» |
  | SVG как URL, CSS вместо препроцессора | медленный dev-сервер / сборка: меньше работы для сборщика |
  | Явные расширения в импортах | медленный резолв в dev: `'./Component.tsx'` вместо `'./Component'` |
  | Разогрев файлов dev-сервера (`server.warmup`) | водопад трансформаций при первом открытии в dev |
  | Профиль dev-сервера (`vite --profile`, `vite-plugin-inspect`) | медленный старт — искать медленный плагин, а не гадать |
  | Стабильная форма объектов (V8) | горячий цикл в профиле, где движок помечает деоптимизацию |
  | Event delegation | ванильный DOM; в React события и так делегированы на корень |
